# SoundCloud Playlist Bot

Telegram-бот на **aiogram 3.x + yt-dlp**: принимает ссылку на плейлист (set) SoundCloud,
скачивает все треки, конвертирует их в **MP3 192 kbps** (с встроенными тегами и обложкой)
и отправляет пользователю через `send_audio` с живым прогрессом обработки.

## Возможности

- 🎧 Скачивание плейлистов (`/sets/…`) и одиночных треков SoundCloud
- 🔍 **Поиск по названию/исполнителю**: просто напишите «исполнитель — название»
  (или `/search <запрос>`) — бот вернёт до 20 результатов, по 5 на страницу,
  с инлайн-кнопками листания «⬅️ Назад / Ещё ➡️» и кнопками с номером трека
  для скачивания
- 🎛 Конвертация в MP3 192 kbps через ffmpeg-постпроцессоры yt-dlp
  (`FFmpegExtractAudio` + `FFmpegMetadata` + `EmbedThumbnail`)
- 🖼 Обложка: вшита в файл и отправляется как `thumb` в `send_audio`
  (title / performer / duration — из метаданных)
- ⏳ Прогресс в чате: одно сообщение редактируется (процент скачивания текущего
  трека, счётчики «Готово N/M», «Ошибок»), с троттлингом ~1 правка в 2.5 с
  и обработкой FloodWait
- 🔔 **Автоподписка на плейлисты** (`/subscribe`): бот сам следит за привязанным
  плейлистом и присылает новые треки, как только они там появляются
- 💾 **Кэш треков**: повторно запрошенный трек (вами или другим пользователем)
  приходит мгновенно, без скачивания и конвертации
- 🛡 Защита от абьюза: лимит треков на плейлист, одна работа на
  пользователя, глобальный лимит параллельных скачиваний, `/cancel`
- 📦 Файлы > 50 МБ (лимит Bot API на отправку) уходят как документ
- ❌ Ошибки отдельных треков не роняют плейлист: трек пропускается, причина
  попадает в итоговый отчёт
- 🧹 Временные файлы — в `tempfile.TemporaryDirectory`, удаляются гарантированно

## Структура проекта

```
soundcloud_bot/
├── bot.py              # entrypoint: логирование, Bot, Dispatcher, polling, монитор
├── handlers.py         # команды, антифлуд, оркестрация работ, отправка треков
├── downloader.py       # обёртка над yt-dlp (asyncio.to_thread) + progress hooks
├── progress.py         # ProgressTracker: очередь событий, рендер, троттлинг правок
├── search.py           # поиск треков (scsearch), пагинация 5/стр, кэш результатов
├── monitor.py          # фоновая проверка подписок, рассылка новых треков
├── storage.py          # подписки: JSON-хранилище subscriptions.json
├── cache.py            # кэш MP3 (TTL + LRU), индекс по ID трека
├── config.py           # загрузка .env, константы и лимиты
├── __init__.py
requirements.txt
.env.example
Dockerfile
README.md
subscriptions.json     # создаётся автоматически при первой подписке
cache/                 # кэш MP3-файлов (создаётся автоматически)
```

## Требования

- **Python 3.11+**
- **ffmpeg** (обязателен: yt-dlp использует его для извлечения/конвертации аудио
  и встраивания обложки)
- Доступ бота к Telegram API (исходящие соединения на `api.telegram.org`)

### Установка ffmpeg

| ОС | Команда |
|----|---------|
| Debian/Ubuntu | `sudo apt update && sudo apt install -y ffmpeg` |
| Alpine | `sudo apk add ffmpeg` |
| macOS | `brew install ffmpeg` |
| Windows | `winget install Gyan.FFmpeg` (или скачать сборку с ffmpeg.org и добавить в PATH) |

Проверка: `ffmpeg -version`

## Быстрый старт (локально)

```bash
# 1. Клонируем/заходим в папку проекта
cd <этот-каталог>

# 2. Создаём виртуальное окружение
python -m venv .venv
# Linux/macOS:
source .venv/bin/activate
# Windows (PowerShell):
# .venv\Scripts\Activate.ps1

# 3. Ставим зависимости
pip install -r requirements.txt

# 4. Настраиваем окружение
cp .env.example .env          # Windows: copy .env.example .env
# и вписываем в .env токен от @BotFather: BOT_TOKEN=...

# 5. Запускаем (из корня проекта, там же где папка soundcloud_bot/)
python -m soundcloud_bot.bot
```

Бот работает по long polling — веб-сервер и внешний IP не нужны.

## Запуск через Docker (опционально)

```bash
# Собрать образ
docker build -t soundcloud-bot .

# Запустить (секреты — из .env файла рядом; том sc-bot-data хранит подписки и кэш)
docker run -d --name sc-bot --env-file .env \
    -v sc-bot-data:/data --restart unless-stopped soundcloud-bot
```

В образе уже установлен ffmpeg. Временные файлы пишутся в `/tmp` внутри контейнера.

## Конфигурация (.env)

| Переменная | По умолчанию | Описание |
|---|---|---|
| `BOT_TOKEN` | — | **обязательно**, токен от @BotFather |
| `LOG_LEVEL` | `INFO` | уровень логирования |
| `MAX_PLAYLIST_TRACKS` | `500` | максимум треков на плейлист |
| `PROGRESS_UPDATE_INTERVAL` | `2.5` | сек между правками сообщения прогресса |
| `MAX_ACTIVE_JOBS` | `3` | сколько плейлистов обрабатывается одновременно |
| `GLOBAL_DOWNLOAD_CONCURRENCY` | `2` | лимит одновременных скачиваний треков |
| `TRACK_TIMEOUT_SECONDS` | `600` | таймаут одного трека |
| `WORK_DIR` | системный temp | каталог для временных файлов |
| `SOUNDCLOUD_CLIENT_ID` | — | fallback client_id, если yt-dlp не смог его получить сам |
| `PLAYLIST_CHECK_INTERVAL` | `1800` | как часто проверять подписки (сек) |
| `MAX_SUBSCRIPTIONS_PER_USER` | `5` | лимит подписок на пользователя |
| `MAX_NEW_TRACKS_PER_CHECK` | `10` | макс. новых треков за одну проверку |
| `SEND_DELAY_SECONDS` | `3` | пауза между автоотправками |
| `CACHE_ENABLED` | `1` | кэш треков вкл/выкл |
| `CACHE_DIR` | `cache/` | каталог кэша |
| `CACHE_TTL_HOURS` | `72` | время жизни трека в кэше |
| `CACHE_MAX_SIZE_MB` | `2048` | лимит размера кэша |

## Поведение бота

- `/start` — приветствие и инструкция
- `/help` — возможности и лимиты
- `/cancel` — отменить текущую обработку
- `/search <запрос>` — поиск трека на SoundCloud по названию/исполнителю
  (можно отправить команду reply'ем на сообщение с текстом); результат —
  до 20 треков по 5 на страницу с кнопками листания «⬅️ Назад / Ещё ➡️»,
  кнопка с номером скачивает выбранный трек; без команды поиск запускается
  любым текстовым сообщением без ссылки
- `/subscribe <ссылка>` — подписаться на плейлист: новые треки приходят сами
  (можно отправить команду reply'ем на сообщение со ссылкой);
  текущий состав считается уже известным — следим только за будущими добавлениями
- `/unsubscribe <ссылка>` (или `/unsubscribe all`) — отписаться
- `/mysubs` — список ваших подписок
- `/stats` — статистика: подписки и кэш
- сообщение со ссылкой на SoundCloud → «⏳ Начинаю обработку плейлиста…»,
  далее это сообщение редактируется, показывая прогресс:

  ```
  ⏳ Обрабатываю плейлист (12 трек(ов))
  «My Playlist»

  📥 Скачивание: 45.0% — Artist — Track Name
     512 КБ/с · 3.2/7.1 МБ · осталось ~8 с

  ✅ Готово: 3/12
  ❌ Ошибок: 0
  ```

- по завершении — итоговый отчёт: сколько треков отправлено, сколько пропущено и почему.

## Автоподписки и кэш

**Подписки.** Фоновый монитор раз в `PLAYLIST_CHECK_INTERVAL` (30 мин по
умолчанию) обходит все подписки, сравнивает состав плейлиста с отправленным
(по ID треков SoundCloud) и рассылает новые треки с паузой `SEND_DELAY_SECONDS`
между отправками. Если плейлист недоступен 3 проверки подряд — предупреждение
пользователю, 10 подряд — автоотписка. Подписки хранятся в `subscriptions.json`
(атомарная запись, переживает перезапуск).

**Кэш.** После успешной отправки MP3 кладётся в `cache/` под именем
`<track_id>.mp3`. Любой следующий запрос этого трека (любым пользователем
или автоподпиской) отдаётся из кэша мгновенно. Чистка: TTL 72 ч с последнего
использования + LRU-лимит 2 ГБ (удаляется самое давно неиспользуемое).
Отключается `CACHE_ENABLED=0`.

⚠️ Для автоподписок бот должен работать **24/7** (long polling не требует
внешнего IP, но процесс должен жить). Для перезапусков сервера удобен
`--restart unless-stopped` в Docker или systemd-unit.

## Обработка ошибок

| Ситуация | Поведение |
|---|---|
| Приватный / удалённый плейлист | понятное сообщение пользователю, работа завершается |
| Трек недоступен | трек пропускается, причина — в итоговом отчёте, плейлист продолжается |
| FloodWait (`TelegramRetryAfter`) | сон на `retry_after` и повтор (как для правок прогресса, так и для отправки) |
| Файл > 50 МБ | отправляется `send_document` с пояснением |
| Сбой конвертации / нет MP3 | трек пропускается с причиной, ошибка логируется |
| Трек защищён DRM | понятное сообщение «Трек защищён DRM и не может быть скачан» |
| Таймаут трека | трек пропускается («таймаут скачивания») |
| Нет ffmpeg | понятное сообщение («Не найден ffmpeg…») |
| Плейлист подписки недоступен | 3 неудачи — предупреждение, 10 — автоотписка с сообщением |
| Бот удалён из чата | тихая автоотписка (по `TelegramForbiddenError`) |
| Любая непредвиденная ошибка | traceback в лог, пользователю — аккуратное сообщение |

## Примечания

- **client_id SoundCloud**: yt-dlp получает его автоматически. Если SoundCloud
  что-то меняет и извлечение падает с ошибкой авторизации, можно задать
  `SOUNDCLOUD_CLIENT_ID` в `.env` (fallback предусмотрен в `downloader.py`).
- **yt-dlp обновляйте регулярно** (`pip install -U yt-dlp`): SoundCloud
  периодически меняет API, и свежие версии чинят скачивание первыми.
- **Асинхронность**: все вызовы yt-dlp уезжают в поток через `asyncio.to_thread`.
  Progress hook вызывается из потока yt-dlp и лишь неблокирующе кладёт событие
  в `asyncio.Queue`; потребитель очереди живёт в event loop и правит сообщение
  с троттлингом — это корректный мост «поток → event loop» без гонок.
- **Параллелизм**: треки внутри плейлиста качаются последовательно (надёжнее
  для метаданных/обложек), а глобальный семафор ограничивает суммарное число
  одновременных скачиваний между плейлистами.
